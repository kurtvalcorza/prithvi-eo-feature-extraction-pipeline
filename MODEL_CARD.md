#### Description

`ibm-nasa-geospatial/Prithvi-EO-2.0-300M` at revision `9eb1b1102806593963daa333bcc491b1c6f8562f` is the 300 M-parameter member of Prithvi-EO-2.0 (Szwarcman et al., 2024), NASA and IBM's foundation model family for Harmonized Landsat Sentinel-2 imagery, in the variant without temporal and location embeddings. It is a ViT-L masked autoencoder: a 3-D patch embedding turns a (6 bands, T dates, H, W) stack into 1 × 16 × 16 cubes (a token per patch per date), a fixed 3-D sin/cos positional embedding is added, 24 transformer blocks of width 1024 with 16 heads encode the visible tokens, and an 8-block decoder of width 512 predicts the pixels of the masked ones; pretraining masked 75 % of the patches of 4.2 M global HLS samples (four dates of 224 × 224 pixels, six bands: blue, green, red, narrow NIR, SWIR 1, SWIR 2) and minimised the reconstruction MSE. The checkpoint packaged here, `Prithvi_EO_V2_300M.pt` (1,326,658,396 bytes, SHA-256 `faab2c8b…`), is the state dict of both halves: 294 encoder tensors and 104 decoder tensors, 330,419,712 parameters plus the fixed positional-embedding buffers. It is the base that DIMER's flood and burn-scar pipelines were fine-tuned from.

What this repository adds is the `PrithviFeaturePipeline` class in `src/prithvi_eo_feature_extraction_pipeline/pipeline.py`: manifest verification of the 7-file Hub snapshot before any model library is imported (`verify_snapshot`, which also checks the converted file against its pinned digest when present), fresh-clone staging at the pinned revision (`stage_missing_files`), a **static audit of the pickle** that lists every global it would import with `pickletools` and refuses anything outside the allow-list (`audit_pickle`, digest pinned), a **one-time conversion** through torch's weights-only unpickler into a strictly loaded model whose state dict is saved as safetensors (`convert_model`), model construction from the installed `terratorch` package with the pinned configuration (`build_model`), two record contracts with named ceilings (`validate_stacks` for 1–4-date embedding stacks, `validate_inputs` / `validate_dataset` for 512 × 512 labelled chips), **embeddings** — the CLS token and the mean of the patch tokens of the final layer, or the full token grid (`embed`), **masked reconstruction** scored against a mean-fill baseline (`reconstruct`), **patch-level labels** from pixel masks (`patch_labels`), a **bounded linear probe** on the frozen patch tokens of a chosen encoder block with validation-loss epoch selection (`adapt`), patch-level prediction and IoU / F1 / precision / recall against the majority baseline (`predict`, `evaluate`), and a safetensors probe artifact that is digest-verified and scope-checked before deserialization (`save_artifact`, `from_artifact`). `samples.py` — the burn-scar pipeline's module verbatim — pins the dataset tarball and its 88 members, extracts exactly those members without `extractall`, assigns the model repository's split roles, and reads/writes GeoTIFF pairs for BYOD with `tifffile`; `metrics.py` holds the confusion-matrix metrics and the majority baseline.

Two things about this profile are stated rather than hidden. **The adaptation is a probe, not a fine-tune**: the encoder is run once per scene and never changed, the probe reads the tokens of encoder block 12 (zero-based `FEATURE_LAYER = 11`, chosen on the validation split during the build — the last, reconstruction-oriented block scored lower: test F1 0.77 against 0.90), and the frozen comparison point is the zero head, which is the majority baseline by construction. **The labelled scenes are single-date and 512 pixels**, while the model was pretrained on four-date 224-pixel samples; `terratorch` interpolates the positional embedding for other sizes and date counts, and the card reports what that gives on this sample, not what the model would do on its native shape.

#### Intended Use and Limitations

###### Primary Intended Uses

Three tasks are exposed. **Embeddings:** input is a (6, T, H, W) reflectance stack of one to four dates with sides that are multiples of 16 in [64, 1024] (or one to four GeoTIFFs in chronological order); output is the CLS embedding and the mean patch-token embedding (1024 floats each) and, on request, the (T, H/16, W/16, 1024) token grid — features for retrieval, clustering, change screening or as inputs to a downstream model. **Masked reconstruction:** the pretraining task at a chosen mask ratio with a seeded mask, reporting the masked-patch MSE beside a mean-fill baseline and optionally the reconstructed stack — a check that the encoder–decoder pair is intact and a way to see what the model has learned about a site. **Adaptation to labelled scenes:** given at least four 512 × 512 chips with masks (0 / 1 / −1), the pipeline trains a linear probe on the frozen block-12 tokens for the patch-level version of the labels and exports it as a 17 KB artifact; `predict` then returns one class per 16 × 16 patch. Envisioned application domains are Earth-observation research and prototyping — screening HLS archives by embedding similarity, quick linear-probe baselines for a new labelled task before a fine-tune is attempted, teaching what a geospatial foundation model represents. In a larger system the pipeline is an embedding service and a probe baseline whose outputs feed a downstream classifier, a retrieval index or an analyst's review; it is not a segmentation model, a change-detection system or a burned-area product.

###### Primary Intended Users

Intended users are Earth-observation scientists and machine-learning engineers who work with HLS or Sentinel-2 scenes, in research or public service. The pipeline assumes its users understand that the model learned six specific bands at a specific scaling and that band order and reflectance units are part of the contract; that an embedding is a representation with no built-in meaning until a probe or a similarity is defined on it; that a patch-level probe resolves 16 pixels and a fine-tuned decoder resolves one; that neighbouring scenes of one site are near-duplicates, so splits must be by site or tile; that the majority baseline is the number to read first on scenes with little of the positive class; and that a 12-scene evaluation is a sanity check, not a measurement of skill.

###### Out-of-scope use cases

1. **Capability boundary:** the pipeline embeds and reconstructs HLS-like stacks and fits a linear probe on frozen tokens. It does not fine-tune the encoder or the decoder, does not segment at the pixel level, does not use temporal or location coordinates (the `TL` variants do), does not tile scenes larger than 1024 pixels, does not mask clouds or correct atmosphere, and does not reproduce the GEO-bench scores of the paper.
2. **Input boundary:** embedding stacks have exactly six bands in the HLS order, one to four dates, and sides that are multiples of 16 in [64, 1024]; labelled chips are exactly 512 × 512; values must be finite reflectance in [−0.5, 2] after scaling (values above 1 are divided by 10 000); labels hold only 0, 1 and −1; datasets hold 4..2,000 records with at least one positive pixel and, for the probe, at least one positive patch. Other band sets, radiometric products (digital numbers other than HLS's, radiance), or label vocabularies are not inputs.
3. **Decision boundary:** not for autonomous action on an embedding, a similarity or a probe map — damage assessment, land-use decisions, enforcement, insurance — without verification against the deployment's own reference over a representative set of scenes and an analyst's review. A probe map from this pipeline is an experiment output at 16-pixel resolution, not a product.
4. **Provenance boundary:** not for settings that require the upstream serialized checkpoint to be executed as-is, or that forbid any one-time unpickling of a third-party checkpoint even through a restricted loader after a static audit; the trust boundary is documented under *Mitigations* and in `docs/WEIGHTS.md`.

#### Factors

###### Groups

The pipeline's inputs are satellite reflectance scenes, not records about people, so age, gender, skin type and socioeconomic status are not attributes of any input and no demographic evaluation applies. The relevant groups are geographic and physical: biomes, land covers and seasons, cloud and snow conditions, terrain, and the HLS tile and year. Upstream reports GEO-bench aggregates across tasks; this repository measures one site (four dates over T13REM, Mexico, 2018) for reconstruction and 12 burn-scar test scenes from the contiguous United States (2018–2021) for the probe, pooled over patches, and reports no per-tile numbers — how well the embeddings serve a region, a biome or a season is therefore unmeasured here, and a deployment should measure it there. Communities in landscapes under-represented in the 4.2 M pretraining samples bear the error of a representation that fits them less well, silently.

###### Instrumentation

The instruments are Landsat 8's OLI and Sentinel-2's MSI as harmonised by HLS: surface reflectance at 30 m in HLS S30/L30 tiles, six of the harmonised bands taken (B02, B03, B04, B8A, B11, B12), stored as int16 digital numbers × 10 000 (the example tiles) or as float32 reflectance in [0, 1] (the burn-scar scenes). The model's own instrument is its patching, 16 × 16 pixels per token per date (a 480 m square), so a probe map cannot resolve anything narrower, and its positional embedding, fixed for 224 × 224 × 4 and interpolated for other shapes. Instrument and processing defects reach the model as feature error — a different atmospheric correction, cloud or smoke residue, terrain shadow, a band-order mistake, a date order reversed — and the pipeline detects none of them: validation checks shapes and ranges, not radiometry or chronology.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `terratorch==1.2.13` (which brings torchgeo, lightning, timm, segmentation-models-pytorch, albumentations, rasterio and others as its own dependencies; the pipeline imports only `terratorch.models.backbones.prithvi_mae.PrithviMAE`), `tifffile==2026.9.15`, `numpy==2.5.3`, `safetensors==0.8.0`, `huggingface-hub==1.32.0` (`pyproject.toml`). The model is float32 as shipped and runs in float32 (`device` defaults to CUDA when visible, CPU otherwise); the recorded runs are under *Runtime* (load 22 s, a four-date 448 × 560 series embedded in 0.6 s, a 512 × 512 scene in 0.05 s, 2.7 GB of GPU memory on an RTX 5070 Ti laptop GPU; a laptop CPU embeds a scene in about 2 s). Data environment: the model assumes HLS-like surface reflectance of the six bands at the pinned statistics, one to four dates of the same site; it degrades, without any error, on other sensors, other radiometric products, other band orders, and on shapes far from its 224 × 224 × 4 pretraining geometry.

#### Metrics

###### Performance Measures

Two kinds of number are reported. For **reconstruction**, `reconstruct` returns per record the masked fraction, `masked_mse` — the pretraining loss: the MSE over the masked patches in standardised units — and `baseline_mean_fill_mse`, the same quantity for a matte that fills every masked patch with the per-band, per-date mean of the visible pixels; the model is read as intact when it beats that baseline. For the **probe**, `evaluate` reports, exactly as `metrics.segmentation_metrics` names them but over 16 × 16 patches instead of pixels (patches with fewer than half their pixels labelled excluded): `iou` per class, `mean_iou`, `accuracy`, and for the positive class `precision`, `recall` and `f1`, plus the confusion matrix, the labelled-patch count and the positive fraction. Three comparison points are read together: the **majority baseline** (`majority_baseline`, every patch predicted negative — its accuracy equals the negative fraction and its positive-class IoU is 0), the **zero head** (the frozen pipeline before adaptation, identical to the baseline by construction), and the **probe**. The positive-class IoU and F1 are the headline because accuracy is dominated by the negative class. Embeddings themselves carry no metric; the notebook prints cosine similarities between the four dates' embeddings as an observation. Every number in this repository is sample-sanity evidence on one site and on 12 test and 8 validation scenes from one seeded run with no dispersion estimate; the GEO-bench results of the paper are not reproduced or claimed.

###### Decision thresholds

The probe's decision rule is an `argmax` over the two per-patch logits, equivalent to a 0.5 threshold on the positive-class softmax score; `predict` returns both scores so a deployment can apply its own threshold, and the pipeline sets none. The limits fixed during development are input-contract limits, not decision thresholds — the stack shape and date range, the 512 × 512 chip size, the six-band count, the reflectance range after scaling, the label vocabulary, the 4..2,000 record range, the 0.5 pixel-fraction rules that turn a pixel mask into patch labels, the 0.75 default mask ratio — chosen so that a rejection names a real defect and an acceptance never means "radiometrically correct". An operator who needs a threshold (a minimum probe score, a similarity cut-off for retrieval, a maximum reconstruction error before a scene is flagged) must set it from verification against their own labels, weighing the cost of a miss against a false alarm, and own it. `adapt` selects the epoch with the lowest validation loss, which is the only selection this repository performs at run time; the feature layer was selected on the validation split during the build and is recorded as such.

###### Approaches to uncertainty and variability

Reported metrics come from one seeded run on **patch-pooled** held-out scenes — 12 test scenes from the burn-scar model repository's test split for the numbers, 8 validation scenes for epoch selection only — with no cross-validation, bootstrap, ensemble or repeated-run averaging, and no dispersion is reported: with 12 scenes of one dataset, any interval would be dominated by which scenes were drawn, and large burns dominate the pooled counts. A caller who needs one evaluates many scenes across sites and years and reports per-scene distributions, and owns that design. Sources of run-to-run variability: the probe's mini-batch order and the reconstruction mask are seeded (`numpy` and `torch` generators), initialisation is the pinned checkpoint and a zero head, and the encoder runs in float32 under `inference_mode`; CUDA kernels are not forced deterministic, so a re-run can differ in the last decimals of the embeddings and of the probe numbers (the reload parity in the build record was exact). The probe's softmax scores are the head's outputs and are **not calibrated probabilities**; no uncertainty on embeddings or reconstructions beyond the reported MSE is produced.

###### Mitigations

1. **Supply-chain integrity:** `MODEL_ID` and the 40-hex `MODEL_REVISION` are module constants; `verify_snapshot()` checks `modelId`, `revision`, and the byte size and SHA-256 of all 7 manifest entries before any load, additionally asserts the checkpoint's digest against the package constant, and raises on the first mismatch (tests flip bytes, change the identity and delete a file and assert each raises). `stage_missing_files()` fetches only manifest-listed files absent on disk, only at `MODEL_REVISION`, only when `allow_download=True`, and refuses a manifest naming another model. `.gitattributes` carries `weights/** -text`.
2. **Executable serialization handled explicitly:** the pickle is not loaded by the runtime path. `audit_pickle` lists every global it would import with `pickletools` (`collections.OrderedDict`, `torch._utils._rebuild_tensor_v2`, `torch.FloatStorage`) and refuses anything else; the audit digest is pinned. `convert_model` runs size → digest → audit before `torch.load(weights_only=True)` (torch's restricted unpickler, which cannot construct arbitrary objects), requires exactly 398 tensors, and loads them with `strict=True` into `PrithviMAE(...)` built from the pinned configuration; the model's state dict is re-saved as safetensors. Tests craft an archive with `os.system` and a plain pickle of a `complex` and assert each is refused before anything is unpickled. The Hub repository's `prithvi_mae.py` is never fetched or imported.
3. **Deterministic, digest-pinned serving file:** `verify_converted` checks size and SHA-256 against `CONVERTED_SHA256` / `CONVERTED_BYTES` (reproduced by two build conversions and the executed notebook); the model loads with `strict=True` and a parameter-count check. With `require_source=False` (a deployment that ships only the converted artifact) the converted file alone is accepted, still digest-verified.
4. **Data integrity and archive safety:** the dataset tarball is pinned by byte size and SHA-256 (`fetch_tarball` hashes it before any member is read and refuses a mismatch); each of the 88 pinned members is pinned again by size and SHA-256 in `SAMPLE_RECORDS`; `extract_pinned_members` streams the archive once, copies out only pinned members through `extractfile`, writes each under its base name in the cache (never at a path from the archive; no `extractall`, no symlinks, no directories), refuses a member digest mismatch, and refuses an archive that lacks a pinned member. Roles come from the model repository's split files; `check_split_disjoint` refuses a scene present in two splits.
5. **Artifact integrity and scope:** the probe is safetensors, not a pickle. `load_artifact` validates the manifest **before** deserialising anything: the artifact format and `format_version`, the recorded base model id, revision and converted-base digest, exactly one weights entry named `adapter.safetensors` that resolves inside the artifact directory, an `adapter.trainable` that is exactly `probe`, a `feature_layer` in 0..23, and a tensor list equal to exactly `probe.weight`, `probe.bias`, `feature_mean`, `feature_std`; the safetensors keys and shapes must then match. The weights file's SHA-256 is checked against the adjacent manifest — it detects corruption or drift of the file relative to that manifest, not authenticity: an actor who can replace both files can make them agree.
6. **Input integrity:** `embed`, `reconstruct`, `predict`, `evaluate`, `adapt`, `validate_inputs`, `validate_dataset` and `validate_stacks` route through two checkers (one per record kind), so their acceptance criteria cannot diverge; they reject missing keys, wrong shapes, band counts, chip sizes, date counts and side lengths, non-finite values, out-of-range reflectance after scaling, label values outside {−1, 0, 1}, duplicate ids and datasets without a positive pixel or patch; no-data is replaced by 0 as upstream does and values above 1 are scaled by 10⁻⁴, both reported.
7. **Training discipline:** only the probe receives gradients (the encoder runs under `inference_mode` and its tokens are cached), the feature statistics are fitted on the training split only, the learning rate defaults to 10⁻², the epoch is selected by validation loss with the zero head as epoch 0, the class-balancing option is off by default and recorded when on, and `adapt` is transactional — any failure restores the previous probe, statistics, layer and adapter record.
8. **Import boundary:** verification, the static audit and validation run before `torch`, `terratorch`, `timm`, `lightning`, `safetensors` or `huggingface_hub` are imported; `tests/test_import_boundary.py` fails if a rejected request reaches a model library, and an AST check fails if any of them is imported at module level.
9. **Honest scope:** validation is labelled structural, the probe is labelled a probe at 16-pixel resolution, the zero head is labelled the majority baseline, the reconstruction number is labelled beside its baseline, the feature layer is labelled as chosen on the validation split, the softmax scores are labelled uncalibrated, the notebook asserts only what the procedure guarantees plus the one direction a probe must satisfy (above the zero baseline), and no upstream benchmark is claimed.

Not implemented, and therefore not claimed: no encoder or decoder fine-tuning, no pixel-level segmentation, no temporal or location coordinates, no tiling of larger scenes, no cloud masking, no calibration, no per-tile evaluation, and no measurement beyond one site and the 44-scene sample.

###### Risks and harms

1. **A conversion can be subtly wrong:** the evidence is the strict key-and-shape match against the architecture built from the pinned configuration and a reconstruction that beats mean-fill on the upstream tiles, under one `terratorch` version. A future package version that changed a block's semantics while keeping its parameter names would load strictly and silently compute something else; the exact pin is the control.
2. **A pickle audit is an allow-list, not a proof:** the static audit bounds what the unpickler can name; torch's weights-only unpickler bounds what it can construct. The digest pins tie the audited bytes to the loaded bytes, and the unpickle happens once, in the operator's environment.
3. **Embeddings carry no guarantee of meaning:** two scenes can be close in embedding space for reasons unrelated to what the operator cares about (season, sensor, cloud); a retrieval or clustering built on them inherits whatever the pretraining data emphasised, silently.
4. **Resolution optimism:** a probe map at 16-pixel resolution can look like a segmentation; narrow features (fire lines, roads, field edges) are sub-token and lost.
5. **In-distribution optimism:** the probe's scenes come from the burn-scar dataset the sibling fine-tune trained on and from one region and period; a reader who carries the numbers to a new region, biome, sensor or shape draws an unsupported conclusion.
6. **Near-duplicate leakage:** neighbouring scenes of one site are near-duplicates; a split over shuffled scenes makes memorisation look like skill. Neither the model nor this repository can detect a leaking split the operator builds.
7. **Band-order, unit and date mistakes:** a stack with the bands in another order, in radiance units, or with the dates out of order is embedded without complaint; validation catches shapes and ranges, not meaning.
8. **Automation bias and proprietary data:** a clean-looking probe map or a confident similarity invites acting on it without review, and the realistic confidentiality failure is licensed imagery or an unreleased assessment uploaded to a cloud notebook — inference is local, but the runtime may not be the operator's.

###### Use cases

The model must not be used to direct evacuation, aid, insurance, damage assessment, enforcement or land-use decisions, or to produce any map presented as an operational product, without verification against the deployment's own labels over a representative set of scenes and a qualified analyst's review; it must not be used as evidence about Prithvi-EO-2.0's benchmark skill, which this repository does not measure; it must not be used to present a 16-pixel probe map as a segmentation; it must not be used to load or execute the upstream pickle in any way other than the audited, digest-verified, one-time conversion this repository performs; it must not be used to redistribute HLS Burn Scars scenes without the CC BY 4.0 attribution; and it must not be used in any way that breaches the Apache-2.0 terms of the upstream weights or the terms of the deployment that runs the pipeline.

## Input/output contract

- `PrithviFeaturePipeline.from_pretrained(device=None, weights_dir=None, allow_download=False, require_source=True, report=None)`: stages and verifies the snapshot, audits and converts the checkpoint when the safetensors file is absent (reporting through `report`), builds the masked autoencoder from `terratorch` and loads the safetensors strictly. `require_source=False` accepts the digest-verified converted file without the checkpoint.
- `embed(records, *, keep_tokens=False) -> dict` with `model`, `embedding`, `dim`, `embeddings` (per record: `id`, `cls` (1024,), `mean` (1024,), `token_grid` [T, H/16, W/16], `frames`, and `tokens` (T, H/16, W/16, 1024) when kept), `seconds`.
- `reconstruct(records, *, mask_ratio=0.75, seed=0, keep_images=False) -> dict`: `model`, `metric`, `mask_ratio`, `seed`, `results` (per record: `id`, `masked_fraction`, `masked_mse`, `baseline_mean_fill_mse`, and `reconstruction` (6, T, H, W) reflectance + `mask` (T, H, W) when kept), `seconds`.
- `predict(records) -> dict` with `model`, `classes`, `resolution`, `decision_rule`, `predictions` (per record: `id`, `mask` (32, 32) uint8, `scores` (2, 32, 32) float32, `class_fraction`), `seconds`.
- `evaluate(records) -> dict`: `n_records`, `metric`, `model` (`iou` per class, `mean_iou`, `accuracy`, `precision`, `recall`, `f1`, `confusion`, `labelled_pixels` (patches), `positive_fraction`), `baseline_not_burned` (the same fields), `adapted`, `seconds`.
- `adapt(train, val=None, *, epochs=30, lr=1e-2, batch_size=4096, trainable="probe", class_balance=False, feature_layer=11, seed=0, progress=None) -> dict`: the linear probe; returns the trainable count, hyperparameters, `feature_layer`, `features`, `loss`, `n_train_patches`, `positive_fraction_train`, `best_epoch`, per-epoch `history` (epoch 0 = the zero head, each with `train_loss`, `val_loss` and the validation metrics) and `seconds`.
- `save_artifact(output_dir, metadata=None) -> Path` writes `adapter.safetensors` (`probe.weight`, `probe.bias`, `feature_mean`, `feature_std`) + `manifest.json` (format, base model id/revision/key and converted digest, adaptation record with the feature layer, classes, history, tensor names, file size and SHA-256); `from_artifact(...)` / `load_artifact(...)` verify all of that before deserialising.
- `validate_inputs(record)`, `validate_dataset(records, *, min_records=4, max_records=2000, require_labels=True)` and `validate_stacks(records)` raise exactly what the execution path would raise; `check_record` returns one normalised chip; `patch_labels(label, patch=16)` the (H/16, W/16) patch labels. `read_chip(path, band_indices=None)` / `read_mask(path)` / `read_stack(paths)` read GeoTIFFs with `tifffile`; `fetch_sample_dataset(cache_dir=None)` / `fetch_corpus` / `fetch_tarball` / `extract_pinned_members` are the pinned-data primitives; `load_byod_dataset(path)`, `write_sample_pair`, `write_dataset_csv` the BYOD I/O; `split_dataset`, `check_split_disjoint`, `dataset_manifest` the split helpers; `segmentation_metrics`, `confusion_matrix`, `metrics_from_confusion`, `majority_baseline` the metrics.
- `audit_pickle(path, allowed=…)`, `convert_model(path=None)`, `verify_converted(path=None)` and `build_model()` are the serialization primitives.
- Constants: `BANDS` (6), `S2_L1C_BAND_INDICES = (1, 2, 3, 8, 11, 12)`, `MEANS`, `STDS` (HLS digital-number scale), `REFLECTANCE_SCALE = 10000`, `CONSTANT_SCALE = 1e-4` (applied only above 1), `IMAGE_SIZE = 512`, `MIN_SIDE = 64`, `MAX_SIDE = 1024`, `MAX_FRAMES = 4`, `PATCH = 16`, `EMBED_DIM = 1024`, `FEATURE_LAYER = 11`, `FINAL_LAYER = 23`, `NUM_CLASSES = 2`, `CLASS_NAMES = ("not burned", "burn scar")`, `IGNORE_INDEX = -1`, `MIN_RECORDS = 4`, `MAX_RECORDS = 2000`, `PARAMETER_COUNT = 330419712`, `STATE_TENSORS = 398`, `ADAPTATION_MODES = ("probe",)`, `ARTIFACT_FORMAT = "org.valcorza.prithvi-eo-feature-extraction.probe.v1"`, `TAR_SHA256`, `DATASET_REVISION`.

## Deployment notes

| Field | Status |
|---|---|
| Licence | Apache-2.0 (weights, the upstream Prithvi-EO-2.0 code, TerraTorch, and this repository's code) — use, modification, redistribution and commercial use permitted with the licence and notices preserved |
| Weights | Redistributable only as the converted file, not the original: the deployable artifact is the deterministic safetensors derived from the pinned checkpoint, with both identities recorded; this repository redistributes neither |

| Runtime | `terratorch==1.2.13` + `torch==2.14.0` + `torchvision` + `tifffile`; float32; a GPU is advisable for the probe's 32 encoder passes (about 2 s per scene on a CPU); the `terratorch` install is heavy (torchgeo, lightning, rasterio and their dependencies) |
| Deployable files | `prithvi-eo-2.0-300m.safetensors` (1,326,543,456 bytes, SHA-256 `15b8ed6d…`); **the `.pt` file must not be deployed** |
| Input contract | (6, T, H, W) stacks of one to four dates with sides multiples of 16 in [64, 1024] as arrays or GeoTIFFs for embeddings and reconstruction; 512 × 512 chips with 0 / 1 / −1 labels for the probe; surface reflectance in [0, 1] or × 10 000 |
| Sample data | the four example tiles of the model snapshot; the HLS Burn Scars tarball (CC BY 4.0) fetched at run time from the Hub at an immutable revision, 88 pinned members extracted, never vendored |

**Before deploying.** Conversion unpickles the source checkpoint once, through torch's weights-only loader after a static audit with a pinned digest (the notebook converts what it downloads); a deployment that wants no unpickling at all should load only a safetensors file converted and verified once in advance. The deployable artifact is the same file either way.
