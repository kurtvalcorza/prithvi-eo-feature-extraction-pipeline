## Two things this tutorial does that most of the fleet's others do not

**It converts a pickled checkpoint in the runtime and says so.** The upstream file is a torch state-dict pickle; Section 3 prints the static audit (the three globals the pickle would import, 0 violations, the pinned audit digest) and the conversion record (398 tensors, 294 encoder + 104 decoder, the converted file's digest) before the model loads, and the provenance export records `served_from_pickle: false`.

**It adapts a model that has no task head, and says what that means.** The bounded adaptation is a linear probe on frozen patch tokens — the encoder is never trained — so the frozen comparison point is the majority baseline (what a zero head predicts), the metrics are patch-level (one class per 16 × 16 pixels), and the notebook reads the result against the burn-scar row's pixel-level fine-tune on the same scenes rather than presenting it as segmentation.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules (`pipeline.py`, `samples.py`, `metrics.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 7-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes all seven entries and asserts the checkpoint's digest against the package constant; `PrithviFeaturePipeline.from_pretrained(weights_dir=..., report=print)` audits and converts the pickle when the safetensors file is absent, verifies it against the pinned digest, builds the model from `terratorch` and loads it strictly. The pickle is unpickled exactly once, in that conversion, through torch's weights-only loader, after the audit.
- **Stages (§4.1):** `fetch_sample_dataset` (the pinned tarball, extracted) / `load_byod_dataset` (sample acquisition) + the example tiles as `validate_stacks` records → `dataset_manifest` + `validate_dataset` / `validate_stacks` refusal probes (validation, with the ceilings and a dataset digest) → roles from the model repository's splits (train / validation / test) → `pipe.embed` + `pipe.reconstruct` with the mean-fill baseline and `pipe.evaluate` on the zero head with the majority baseline (baseline) → `pipe.adapt` (bounded linear probe) → `pipe.evaluate` on validation and test with the paired comparison (evaluation) → `pipe.predict` probe maps (inference) → `pipe.save_artifact` → `PrithviFeaturePipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the probe's softmax scores are the head's outputs, labelled uncalibrated; the decision rule is the argmax with no threshold, and the notebook says the threshold and its cost trade-off are the deployment's to set; the reconstruction MSE is reported in standardised units beside its baseline.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the majority baseline is scored on the same patches as every probe number and the mean-fill baseline on the same masked patches as every reconstruction number, and every metric is labelled as patch-pooled tutorial sample-sanity evidence from 12 test scenes with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** roles come from the splits published beside the burn-scar checkpoint, never from shuffling scenes; validation loss selects the epoch and the test scenes are used for nothing but the final evaluation; the notebook states that neighbouring scenes are near-duplicates and that real data must be split by site or tile; the feature statistics are fitted on the training split only; the feature layer was chosen on the validation split during the build and is stated as such. In BYOD mode the seeded split is by scene and the notebook says to group by site.
- **Ceilings (VAL6):** the scene size, the band count and order, the reflectance range and scaling, the label vocabulary, the record range and the stack shape (1–4 dates, sides multiples of 16 in [64, 1024]) are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user scenes flow through the same validation, baseline, probe, evaluation, inference, export and reload cells. The expected zip layout, the band contract and the privacy guidance — licensed imagery and unreleased assessments are restricted data — are stated in the Prerequisites and in Section 4, and a sample pair is written to `outputs/` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
